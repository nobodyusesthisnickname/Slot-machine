## 반드시 유지할 게임 설정
배당은 원금 포함 총 지급 배수입니다. n칩 사용 후 5배 당첨이면 5n칩 지급(사용 시 n칩 먼저 차감).

| 내부 인덱스 | 심벌 | 확률 | 총 지급 배수 | weights |
|---|---|---|---|---|
| 0 | 7 | 0.5% | 10 | 5 |
| 1 | BAR | 1% | 5 | 10 |
| 2 | 체리 | 10% | 2 | 100 |
| 3 | 망고 | 20% | 1.5 | 200 |
| 4 | 종 | 3% | 3 | 30 |
| -1 | 미당첨 | 65.5% | 0 | 나머지 655 |

RTP = 0.005×10 + 0.01×5 + 0.10×2 + 0.20×1.5 + 0.03×3 = 0.69 = 69%.
당첨 확률 합계 34.5%. 총 사용 칩 기준 이론적 미지급 비율 31%이며, 칩 판매액 기준 확정 수익률이 아닙니다. 재사용 칩도 총 사용량에 포함됩니다.
1.5배 확률을 25%로 올리는 방안을 계산만 했습니다. 그렇게 바꾸고 미당첨을 60.5%로 낮추면 RTP 76.5%이지만 적용 요청은 없었고 현재는 20%입니다.
1.5배 당첨(20%)을 "추가 칩 없이 한 번 더 돌리기"로 바꾸는 방안도 계산만 했고 **적용하지 않기로 했습니다**. 재회전에서 또 재회전이 나오면 계속 이어진다고 가정하면 `RTP = 0.39 ÷ (1 − 0.2) = 48.75%`입니다(0.39는 2배 0.20 + 3배 0.09 + 5배 0.05 + 10배 0.05). 한 번 사용으로 평균 1.25회 돌고, 결국 당첨 확률은 17.5%, 미당첨은 약 81.9%입니다. 재회전을 1회만 허용하면 RTP는 46.8%입니다. 일반식은 `RTP = 0.39 ÷ (1 − 재회전 확률)`입니다. 구현하려면 `weights`/`multipliers`뿐 아니라 `spin()` 흐름(칩 차감 없는 재회전, 연속 회전 표시, 누적 이익 계산)도 바꿔야 합니다. 사용자 요청 없이 적용하지 마세요.

초기 잔액 10,000칩, 사용 칩 선택 [10,50,100,250,500,1000], 기본 1000칩(시작 시 1000. v19의 '처음부터'는 '릴 리셋'으로 바뀌어 더 이상 사용 칩을 초기화하지 않음). 최대·기본값은 `app.js`의 `bets` 배열과 `defaultBetIndex`(마지막 항목)로 정해지며, 칩 사용 정보를 껐다 켜도 값은 유지됩니다. 브라우저 메모리에만 저장하므로 새로고침하면 초기화됩니다. 기본 1000이면 초기 잔액으로 최대 10번 회전할 수 있습니다. 실제 부스의 '칩 1~2개'와 현재 시뮬레이터의 사용 칩 단위는 서로 다릅니다. 임의로 혼동하지 마세요.

## 추첨과 동작
- crypto.getRandomValues를 사용하며 나머지 연산 편향을 피하는 rejection sampling으로 0~999 정수를 뽑습니다.
- pick()이 먼저 당첨 종류 또는 미당첨을 결정합니다. 릴별 독립 추첨으로 당첨률을 계산하는 구조가 아닙니다.
- 당첨이면 세 릴이 같은 심벌. 미당첨이면 임의 조합을 만들되 세 개가 모두 같으면 다시 뽑습니다.
- 회전 애니메이션은 90ms 간격 심벌 교체, 릴 정지는 `app.js`의 `stopTimes=[2000,2500,4000]`ms입니다(릴1/릴2/릴3, 회전 시작 기준. v19는 900/1320/1740ms였음). 마지막 릴이 멈출 때(4000ms) 지급과 `busy` 해제가 일어나므로 한 번 회전에 약 4초가 걸립니다. 실제 연속 스크롤 릴이 아닙니다.
- busy로 중복 실행 차단. 잔액 부족하면 실행 불가.
- 레버 클릭/포인터 드래그 지원, 드래그 후 클릭 중복 억제. --pull 값으로 막대와 손잡이 회전, 자동 당김 클래스는 560ms 후 해제.
- 선택적 document.modelContext API가 있을 때만 read_slot_state/spin_virtual_slot 등록. 이 API 없이 일반 브라우저에서도 작동하도록 가드되어 있습니다.

## 합의된 UI 방향
- 검정/금색 입체 프레임, 붉은 커튼 배경과 어두운 바닥(대리석). 배경은 `body:before`에서 `blur(2px) brightness(1.3) saturate(1.2)`로 처리하며 어두운 덮개 그라데이션은 없습니다(이전 v19는 `blur(7px)`+어두운 덮개라 배경이 거의 안 보였음). 블러를 아주 없애지는 않았습니다.

## 심벌 변경 이력과 현재 표시 방식
초기 구슬/마름모/별을 체리/레몬/종으로 변경. 7/BAR/종 디자인은 최대한 유지하고 과일 잎 광택을 반복 조정했습니다. 이후 두 PNG를 통합하고 레몬 자리를 체리, 기존 체리 자리를 망고로 변경했습니다.
현재 순서: 7 → BAR → 체리 → 망고 → 종.

현재 실제 렌더링 자산은 `assets/slot-symbols-hd.png`(4344×1448 투명 PNG)입니다. 이미지 생성 도구의 보정 출력은 2172×724였고, 이후 Lanczos로 가로·세로 2배 확대했습니다. 픽셀 수 확대를 실제 원본 세부정보 복원으로 과장하지 마세요. 생성형 보정으로 과거 원본과 미세한 형태 차이가 있을 수 있습니다.

app.js의 spriteBoxes는 [x,y,width,height] 좌표이며 아래 순서로 지정됩니다:
[[95,326,721,773],[884,466,853,491],[1801,310,805,799],[2658,305,849,811],[3516,289,767,832]]
spriteWidths = [75.0732,89.28821,84.03959,88.19475,79.88444]. 각 부모 내 SVG 너비 비율(%)입니다. v19 값([78.0732,92.28821,87.03959,91.19475,82.88444])에서 각 3%p씩 줄인 값이며(v18→v19의 5% 축소 이후 추가 축소), 큰 릴과 배당표에 모두 적용됩니다.
symbolMarkup()이 인라인 SVG viewBox를 만들어 각 심벌만 보이게 합니다. SVG의 image는 전체 PNG를 가리킵니다. overflow:hidden으로 이웃 심벌을 차단하고 flex 가운데 정렬을 사용합니다. 큰 릴과 배당표 모두 같은 함수를 사용합니다.

이전에는 background-size:500%와 0/25/50/75/100% 위치를 사용했는데, 망고 잎이 종의 1/5 구역에 걸쳐 종 칸 왼쪽에 초록색 조각이 보였습니다. 균등 5분할 표시로 되돌리지 마세요.
style.css에는 예전 배경이미지 선언이 일부 남아 있지만 마지막 .symbol,.sprite{background-image:none;...} 규칙이 덮어씁니다. CSS가 누적 수정되어 한 줄 압축과 후반 override가 섞여 있습니다. 정리할 경우 미디어 쿼리 우선순위와 회전 상태를 보존하세요.
